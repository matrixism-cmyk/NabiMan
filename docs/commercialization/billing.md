# 나비맨 요금제와 청구 설계

2026-11-11 작성. **설계만** 있다. 결제 대행 연동, 청구 시스템, 확정 가격은 없다. 아래 금액은 모두 인터뷰·파일럿에서 검증할 **가설**이며 판매가가 아니다([roadmap.md](roadmap.md) 「상품과 가격 실험」과 같은 원칙). 세금·영수증 항목은 법률·세무 조언이 아니라 **세무사·회계사에게 확인할 질문 목록**이다.

## 상품 구조

| 구분 | 설치형(고객 서버에 설치) | 호스팅형(우리가 운영, [hosting-model.md](hosting-model.md)의 (a)) |
|---|---|---|
| 계약 단위 | 연간 라이선스 | 월 단위 인스턴스 구독 |
| 기본 과금 | 관리 서버 수 또는 사용자 수에 따른 연 요금 | 인스턴스 기본료(월) + 사용량 |
| 라이선스 | `deployment: installed`, 1년 만료, 유예 14일 | `deployment: hosted`, 월 갱신(예: 만료 = 다음 결제일 + 여유), 유예 7–14일 |
| 지원 | 지원 등급별 별도 | 기본 지원 포함, 상위 지원 별도 |
| 운영 책임 | 고객(백업·업그레이드·OS) | 우리(백업·업그레이드·모니터링·TLS) |

### 요금제 초안(가설)

| 요금제 `plan` | 대상 | `max_users` | `max_servers` | 요금제 기능 `features` |
|---|---|---|---|---|
| `starter` | 서버 몇 대의 소규모 팀 | 3 | 5 | — |
| `team` | 일반 운영팀 | 10 | 25 | `recording` |
| `business` | 여러 팀·감사 요구 | 50 | 100 | `recording`, `orchestration`, `graph_3d` |
| `enterprise` | 대규모·폐쇄망 | 계약 | 계약(없음 = 무제한) | 전체 + `mec`(MEC 테스트베드 계약 시) |
| `hosted-remote` | 원격 서버 접속만(호스트 기능 없음) | 10 | 25 | — |

과금 기준 가설: 설치형은 **관리 서버 수**를 1순위로 한다(사용자 수로 받으면 계정 공유 유인이 생긴다는 roadmap의 우려). 사용자 수는 상한으로만 둔다. 이 가설 자체가 인터뷰 대상이다.

## 계량하는 것

호스팅형 청구와 설치형 갱신 협의에 쓰는 값은 모두 `GET /api/usage`에서 온다(필드 정의: [hosting-model.md](hosting-model.md) 「사용량 보고」).

| 청구 항목 | `/api/usage` 필드 | 집계 방법 |
|---|---|---|
| 인스턴스 기본료 | `metering.instance_hours`, `instance.instance_id` | 청구 기간에 인스턴스가 존재한 일수로 일할(실행 시간은 SLA 확인용) |
| 사용자 좌석 | `metering.peak_active_users`, `users.active` | 기간 중 **최대** 활성 계정 수 |
| 관리 서버 | `servers.peak`, `servers.saved` | 기간 중 최대 저장 서버 수 |
| 터미널 사용 | `terminal_sessions.session_hours`, `attached_hours` | 포함량 초과분만(예: 좌석당 월 N시간) — 과금할지는 결정 필요 |
| 저장 용량 | `storage.bytes`, `storage.largest` | 월말 값 또는 일별 표본 평균. 녹화(`session-recordings`)·백업이 대부분 |
| 요금제 확인 | `licence.*` | 청구 요금제와 설치된 라이선스가 같은지 대조 |

주의: `metering.first_sampled_day` 이전은 측정되지 않은 기간이다. 0으로 청구하지 말고 "측정 없음"으로 처리한다. `storage.complete = false`이면 하한값이다.

## 청구서 만드는 흐름

```text
매일 02:00 UTC  컨트롤러 ─ GET /api/usage?from=어제&to=어제 ─► 인스턴스
                  └─ 원본 JSON을 그대로 보관(고객·instance_id·일자, 변경 불가 저장)
월 마감         일별 원본에서 월 최대 좌석·최대 서버·세션-시간 합·월말 저장량 계산
                  └─ 요금제 포함량 비교 → 초과분 → 청구 항목
                  └─ 청구 미리보기를 고객 관리자에게 공개(이의 제기 기간)
청구 확정       청구서 번호·공급가액·부가세·합계 → 결제 대행 청구 → 세금계산서/영수증 발행
미납            라이선스 갱신 보류 → 만료 → 유예(새 사용자·서버 추가만 중지, 데이터 유지) → 계약에 따른 해지 절차
```

- 일별로 받는 이유: 하루가 빠져도 다음 날 같은 기간을 다시 조회하면 된다(원장은 800일 보존). 한 달을 한 번에 받으면 원장이 손상됐을 때 근거가 없다.
- 고객이 자기 인스턴스에서 같은 값을 볼 수 있어야 한다(최고관리자는 `/api/usage` 직접 조회 가능). 화면은 후속 과제.
- 설치형은 외부 송신을 기본으로 하지 않는다. 갱신 때 고객이 `/api/usage` 결과를 내보내 제출하거나, 계약상 동의한 경우에만 자동 보고를 켠다(미구현).

## 한국 결제 수단 후보(연동 없음, 비교용)

| 방식 | 후보 | 맞는 상품 | 확인할 것 |
|---|---|---|---|
| 카드 정기결제(빌링키) | 토스페이먼츠, NHN KCP, KG이니시스, 나이스페이먼츠, 포트원(여러 PG 통합) | 호스팅 월 구독, 소액 설치형 | 법인카드 비율, 정기결제 수수료, 실패 재시도·카드 만료 처리, 사업자 심사 기간 |
| 계좌이체·가상계좌 | 위 PG의 가상계좌, 은행 직접 | 연간 설치형, 공공·대기업 | 입금 대사 자동화, 발주서·계약서 기반 후불 |
| 세금계산서 후불 청구 | 자체 청구 + 전자세금계산서(홈택스 또는 발행 대행 서비스) | B2B 연간 계약 대부분 | 지급 조건(월말 마감 익월 지급 등), 미수금 관리 |
| 해외 카드 | Stripe(국내 법인 직접 가입 가능 여부 확인), Paddle(판매 대행 방식) | 해외 고객 | 환전·해외 매출 신고, 판매 대행 시 세금 처리 주체 |

초기 B2B 고객은 **세금계산서 후불 청구 + 계좌이체**가 가장 흔할 것으로 본다(가설). 카드 정기결제는 호스팅 소형 요금제에서 검토한다. PG를 고를 때 빌링키 보관을 PG에 맡기고 우리 서버에는 카드 정보를 두지 않는다.

## 세금·영수증: 전문가에게 확인할 질문

법률·세무 판단이 아니다. 아래 질문을 세무사·회계사에게 확인한 뒤 확정한다.

1. 설치형 연간 라이선스와 호스팅 월 구독의 매출 인식 시점(일시 인식인지 기간 안분인지)과 부가가치세 공급 시기는 각각 언제인가?
2. 소프트웨어 라이선스 공급과 클라우드(SaaS) 서비스 제공이 부가세 과세 대상·공급 장소 판단에서 다르게 취급되는가? 해외 고객에게 공급할 때 영세율 적용 조건과 필요한 증빙은 무엇인가?
3. 사업자 고객에게 카드로 결제받는 경우 전자세금계산서를 별도로 발행해야 하는가, 카드 매출전표로 갈음되는가? 개인·개인사업자 고객의 현금영수증 의무 발행 대상인가?
4. 사용량 초과 요금(세션-시간, 저장 용량)을 사후 청구할 때 세금계산서 작성일자와 공급가액 산정은 어떻게 하는가? 월합계 세금계산서를 쓸 수 있는가?
5. 해외 결제 대행(Paddle 같은 판매 대행)을 쓰면 판매자(공급자)는 누구로 보는가? 국내 매출 신고와 원천징수·부가세 처리는 어떻게 되는가?
6. 연간 선불 계약의 중도 해지 환불, 미사용 기간 반환은 수정세금계산서로 처리하는가? 약관에 무엇을 적어야 하는가(약관 문구는 법률 검토 별도)?
7. 공공기관 판매 시 조달 등록(나라장터·디지털서비스몰), GS 인증 요구 여부, 계약 방식별 청구·증빙 차이는?
8. 개인정보 처리 위탁: 호스팅형에서 고객 서버 접속 정보·세션 녹화를 우리가 보관하는 것이 개인정보 처리 위탁에 해당하는가, 계약서·처리방침에 무엇이 필요한가(법률 검토)?

## 사용자가 정해야 할 사업 결정

- 설치형 과금 단위: 서버 수 중심인지, 사용자 수 병행인지. 요금제별 한도 값.
- 요금제별 포함 기능(`recording`·`orchestration`·`graph_3d`·`mec`)과 아직 막지 않은 세 기능을 실제로 막을지, 막는다면 어디서(화면만 / 서버도).
- 유예 기간(기본 14일)과 유예 뒤 정책(지금: 추가만 중지). 더 강한 제한(읽기 전용 등)이 필요한지.
- 호스팅형 기본료·포함 사용량·초과 단가, 저장 용량 과금 여부, 세션-시간 과금 여부.
- 지원 등급과 응답 시간(24시간 대응을 판매할지).
- 결제 수단과 PG 선택, 해외 판매 여부.

# 원격 관리 화면 기능·사용성 검토

검토 대상: https://man.bebo.kr/#remote/remote
검토일: 2026-09-24

운영 주소는 브라우저에서 로그인 화면까지 확인했다. 운영 계정으로 로그인하지 않았으며 운영 서버·세션·링크는 변경하지 않았다. 기능 검토는 현재 프런트엔드 소스와 별도 데이터 디렉터리의 로컬 서버에서 실제 tmux 세션을 사용했다. 아래 수정은 소스에 반영됐고 운영 반영 전이다.

## 주요 발견과 조치

| 기능 | 발견 | 조치 / 판단 |
|---|---|---|
| 분리 터미널의 우측 영역 | FitAddon은 xterm 요소의 padding을 차감하지만 부모 컨테이너의 padding은 차감하지 않는다. 기존 부모 padding 때문에 본문이 스크롤 영역을 침범할 여지가 있었다. | padding을 xterm 요소로 이동하고 본문을 컨테이너 안으로 제한했다. 창 크기 조절 핸들 공간도 분리했다. |
| tmux 스크롤 잔상 | `convertEol: true`가 PTY의 LF를 CRLF로 바꾸어 tmux의 커서 상대 갱신 위치를 어긋나게 했다. 반복 스크롤 때 이전 위치 표시가 여러 행에 남고 글자가 지워지는 현상을 브라우저에서 재현했다. | `convertEol: false`로 실제 PTY 출력을 보존했다. 수정 후 200줄 기록을 스크롤했을 때 위치 표시가 한 개만 남고 각 행이 정상 표시되는 것을 검증했다. |
| tmux 기록 스크롤 | tmux는 대체 화면 안에서 자체 기록을 관리한다. xterm 기본 스크롤바는 tmux 기록 길이를 나타내지 않아 드래그가 기대대로 동작하지 않는다. | 소유자 터미널의 비활성 기본 스크롤바를 없애고, 휠과 동일하게 tmux에 전달되는 이전/다음 출력 버튼 및 휠 영역을 제공했다. 이 영역은 전체 기록 위치를 드래그하는 스크롤바가 아니다. 공유 관람 화면의 스크롤 정책은 변경하지 않았다. |
| 같은 세션을 반복 분리 | 같은 세션의 창이 계속 추가되어 같은 셸이 중복 표시되고 창 크기 변경이 서로 영향을 줄 수 있었다. | 이미 열린 세션이면 기존 창을 복원하고 앞으로 가져온다. 새 세션 생성 기능은 유지한다. |
| 공유 링크의 ‘취소’ | 모달 닫기/입력 취소처럼 읽히지만 실제 동작은 링크 DELETE다. | ‘삭제’로 바꾸고, 확인문에 링크 접근 종료와 세션 유지의 차이를 명시했다. 모달 종료는 ‘닫기’다. |
| 생성 직후 링크 중복 | 방금 생성한 링크가 별도 결과 영역과 기존 링크 목록에 동시에 표시됐다. | 목록에 한 번만 표시하고 새 링크의 전체 주소를 선택·복사할 수 있게 했다. |
| 내부 공유 / 링크 공유 | 계정이 있는 다른 사용자가 접근하도록 하는 기능과 외부 공유 링크 발급 기능이 모두 ‘공유’로 읽혔다. | 전자는 ‘내부 사용자 공유’로 명명했다. 두 기능은 권한 범위가 다르므로 제거·통합하지 않는다. |
| 공유 모달 계층 | 분리 창 내부에 모달이 렌더링되어 다른 창의 쌓임 순서와 간섭할 수 있었다. | document.body 포털로 이동했다. dialog 이름, 모달 의미, 키보드 포커스 순환, Escape 닫기를 추가했다. |
| 삭제 실패 피드백 | 공유 링크 삭제 응답을 확인하지 않고 성공 표시·목록 갱신을 수행했다. | 실패 메시지를 표시하고 목록과 생성 결과를 유지한다. 삭제 중 중복 클릭도 차단한다. |
| 세션 종료 / 창 닫기 | 세션 카드의 ×와 분리 창의 ×는 결과가 달랐다. | 카드에는 ‘세션 종료’를 표시했다. 창의 ×는 기존의 세션 유지 안내를 유지한다. 종료 API 실패 시 창을 닫지 않도록 했다. |
| 서버 삭제·세션 변경·전체 점검 | 일부 API 실패를 사용자에게 표시하지 않고 다음 화면으로 진행하거나 갱신만 했다. | 서버 삭제, 세션 이름/공유/유지 변경, 전체 점검 실패를 표시하도록 수정했다. |

## 기능 구성과 중복 여부

- 전체 현황과 개별 서버 상태는 각각 여러 서버의 요약과 한 서버의 상세 점검이다. 서로 다른 범위이므로 유지한다.
- 전체 점검과 개별 점검은 범위가 다르다. 다만 전체 점검의 결과 요약(성공/실패 건수)은 추가하면 좋다.
- 터미널과 명령 실행은 각각 지속되는 대화형 셸과 단발 명령 실행이다. 기능 중복은 아니지만 명령 실행 탭에 차이를 설명하면 선택이 쉬워진다.
- 등록 서버와 빠른 접속은 저장되는 대상과 일회성 대상이다. 현재 안내대로 분리 유지가 적절하다.
- SSH 키 관리와 서버별 키 배포는 키 자체 관리와 특정 서버에 설치하는 작업이다. 역할이 다르다.
- 세션별 공유 모달과 전체 공유 링크 탭은 생성/해당 세션 관리와 전체 발급 내역 관리다. 별도 화면은 유지하되 용어와 삭제 결과는 일치시켰다.
- 창 닫기, 최소화, 세션 종료는 다른 동작이다. 종료를 ×와 구분하는 방향으로 정리했다.

## 후속 개선 항목

1. 공유 링크 생성 기본값은 조작 허용이다. ‘보기 전용 / 함께 조작’ 선택을 생성 버튼 가까이에 명확히 표시하고, 기본 정책을 검토할 필요가 있다.
2. 공유받은 내부 세션에도 관리 버튼이 표시되는지 계정별 검증이 필요하다. 서버가 권한을 거부하더라도 화면에서 불가능한 조작을 숨기거나 비활성화하는 편이 낫다.
3. 빠른 접속의 포트는 parseInt 결과가 없으면 22로 대체된다. 잘못 입력한 값과 빈 값을 구분하고 1–65535 범위의 입력 검증을 제공해야 한다.
4. 전체 점검의 진행 상황·완료 건수, 끊긴 세션 재접속 안내, 좁은 화면에서 세션 카드 버튼 줄바꿈을 후속 사용자 흐름 검증에 포함해야 한다.
5. tmux 전체 기록 위치를 드래그하는 진짜 스크롤바가 필요하다면 서버의 기록 길이·현재 위치를 동기화하는 별도 기능이 필요하다. 이번 변경은 실제로 동작하는 기록 버튼과 휠 영역을 제공한다.

## 검증 근거

- 수정 전 로컬 분리 창: 부모 폭 718px, 좌우 padding 12px, xterm viewport 폭 706px, 글자 화면 폭 700px. 일반 15px 스크롤바 환경에서는 본문 공간보다 글자 화면이 넓어질 수 있다.
- 수정 후 로컬 분리 창: 글자 화면 오른쪽 725px, 기록 영역 시작 748px, 기록 영역 끝 772px, 크기 조절 핸들 시작 773px. 영역이 겹치지 않는다.
- 실제 tmux에서 200줄 출력 후 기록 버튼으로 copy-mode 진입 및 화면 변경 확인.
- 공유 모달이 분리 창 밖 포털에 표시되고, 링크 생성 후 목록에 한 행만 표시됨을 확인.
- 공유 링크 DELETE 500 응답 주입 시 오류 표시와 링크 유지 확인. 정상 DELETE 시 목록에서 제거 확인.
- 프런트엔드 테스트 43개 통과. 빌드와 타입 검사 통과.
- `frontend/scripts/smoke-terminal-history.js`로 tmux 반복 스크롤과 잔상 부재, 본문/기록/크기 조절 영역 분리 검증.
- 같은 세션을 다시 분리했을 때 창 1개 유지, 최소화된 창 복원, Escape로 공유 모달 닫기 확인.


## 추가 개선: 분리 창 다시 그리기와 기록 위치 이동

- 분리 창 상단의 `화면 다시 그리기`는 같은 WebSocket에서 현재 크기를 보내 tmux 클라이언트를 갱신한다. 세션을 새로 만들거나 터미널 입력을 보내지 않는다.
- 기존 소유자 연결에도 클라이언트 TTY를 저장해, 크기가 바뀌지 않아도 tmux의 전체 재전송을 요청할 수 있게 했다.
- 우측 손잡이는 tmux가 보고한 전체 기록 길이/현재 위치에 따라 표시된다. 트랙 클릭, 손잡이 드래그, 방향키/PageUp/PageDown/Home/End를 지원한다.
- 맨 아래로 이동하면 copy-mode를 종료하고 실시간 출력으로 돌아온다. 드래그 도중 트랙 밖으로 커서가 나가도 포인터 캡처를 유지한다.
- 드래그 요청은 60ms 단위로 합친다. 서버는 세션의 현재 패널에만 접근하며 숫자 위치를 기록 길이 안으로 제한한다. 다른 tmux 모드(선택 화면 등)는 덮어쓰지 않는다.
- 위치 정보는 `history=1`로 접속한 소유자 WebSocket에만 전송한다. 이전 화면과 공유 링크 뷰어에는 새 제어 메시지를 보내지 않는다.
- 테스트: 실제 tmux의 중간/상단/하단 위치, 브라우저 클릭/드래그/키보드, 다시 그리기 후 연결·화면·기록 위치 유지, 기존 창 관리 회귀를 확인한다.

검증 결과: 프런트엔드 43개 테스트, 서버 위치 파서 2개 테스트 및 격리된 릴리스 서버의 실제 브라우저 스모크가 통과했다. 기록 갱신 시 스크롤바의 키보드 포커스가 유지되는 것도 확인했다.
